Build the Agency desktop with npm run build:studio. Packaged users do not need Node or Rust installed.

For source builds, install Git, Node.js 24.18+ and npm 11.6+, and Rust through rustup. The repository selects Rust 1.97.1. Rust also needs a native linker: Xcode command-line tools on macOS, a C/C++ toolchain such as Ubuntu's build-essential, or Visual Studio C++ Build Tools with the Windows SDK on Windows.

git clone https://github.com/vigo-developers/vigo-agency.git
cd vigo-agency
npm ci
npm run build
node public/vigo.mjs capabilities
npm test

These separate commands work in a terminal or PowerShell. Use npm.cmd if PowerShell blocks npm.ps1. Run the examples below from the cloned vigo directory. node public/vigo.mjs avoids a global installation; optional npm link exposes the shorter vigo command.

VIGO 0.3.2 uses API 1.0, City format 1, and Result schema 1.

Supported native targets: macOS 13.5+ on ARM64/x64, Linux glibc on ARM64/x64, and Windows x64. Linux release builds use Ubuntu 24.04. Alpine/musl, 32-bit, and native Windows ARM64 are not provided. Studio needs a graphical session and WebGL 2; Engine does not need a GPU.

2. Build once, then reuse the city

Download a static GTFS ZIP and an OSM .osm.pbf covering the same area. For Boston, use the MBTA static feed and a suitable Geofabrik extract. Save them as feed.zip and region.osm.pbf. GTFS Realtime and OSM XML cannot replace those inputs.

node public/vigo.mjs build --gtfs=./feed.zip --osm=./region.osm.pbf --output=./city
node public/vigo.mjs inspect --city=./city

The output is a complete City directory. An existing output is preserved unless you explicitly add --replace. For several operators, repeat --gtfs; if supplying scopes, give each feed a unique --gtfs-scope in the same order:

node public/vigo.mjs build --gtfs=./bus.zip --gtfs-scope=bus --gtfs=./rail.zip --gtfs-scope=rail --osm=./region.osm.pbf --output=./city

Subsequent queries need the compiled City, not the raw files. Move or archive the entire directory, including its indexes and prepared files. Install a matching runtime on the destination OS/CPU. New active-service patterns or evicted timetable snapshots can still require preparation; changing the source network requires a new City build. Keep the query copy writable for derived caches.

Public pedestrian access is the default. --private-access=endpoints is an explicit assumption that travelers may use mapped private roads at their own endpoints; it does not allow private through routes or establish real permission.

What “loading time” means

Raw Build: command invocation until the City is published and the command returns. Time to first answer: continue through the first complete Query Result. Reopen: start a new runtime on a saved City. Repeated query: run with an already open runtime. Record downloads and installation separately. The compiler's internal totalMs and the native timetable's engineQueryMs are narrower measurements, not full caller elapsed time.

3. Route: transit, walking, and driving

Save this Boston example as route.json. Coordinates are [longitude, latitude]. Alternatively use an exact GTFS stop ID string or {"stopId":"actual-id"}. A street point in CLI JSON uses a coordinate object; do not pass a bare array as the point.

{
  "origin": {"coordinate": [-71.11902, 42.37334]},
  "destination": {"coordinate": [-71.08337, 42.32978]}
}

Replace YYYY-MM-DD with a date covered by your feed's calendar.txt and calendar_dates.txt. Choose coordinates within your OSM coverage. Dates and clocks use the feed's local service day; VIGO does not geocode addresses or silently convert timezones.

node public/vigo.mjs route --city=./city --request=./route.json --service-date=YYYY-MM-DD --time=08:00 --output=./route-result.json
VariantChange to the request above
Walking / drivingAdd --mode=walk or --mode=drive; use coordinate endpoints.
Arrive by 09:00Replace the clock with --time=09:00 --time-preference=arrive.
Departure windowAdd --departure-window=5 to a transit depart-at request: sample integral minutes within ±5; inspect returned choices.
Ordered waypointsAdd "waypoints":[{"coordinate":[-71.1035,42.3654]}] to JSON. Points stay in that order.
At most one transferAdd --max-transfers=1. Zero means at most one boarding. A finite cap with transit waypoints is unsupported.
Transit or walkingAdd "requireTransitRide":false to JSON. Transit otherwise requires at least one vehicle boarding.
Access/egress limit--max-walk=1.2 limits each continuous transit access and egress walk; it does not limit a complete Walk-mode journey.
Search horizon--horizon=480, range 1–2880 minutes. The only objective is earliest_arrival.

For the public JSON command, date, clock, walking budget, and departure window belong in CLI flags. They are not read from identically named JSON fields. Mode, time direction, transfer cap, and horizon also have JSON forms: mode, timePreference, maxTransfers, and horizonMinutes. CLI flags take precedence.

Batch transit queries with CSV

Save routes.csv using columns id,origin_lon,origin_lat,destination_lon,destination_lat. Exact-stop alternatives are origin_stop_id,destination_stop_id; use IDs from your feed. All rows share the selected date/time/options.

node public/vigo.mjs route --city=./city --input=./routes.csv --output=./routes-result.csv --service-date=YYYY-MM-DD --time=08:00

CSV rows go to the output file. The JSON summary and per-row plans go to stdout; there is no automatically written adjacent summary. This CSV path is transit-only. Use JSON Route calls or Matrix for Walk/Drive batches. Missing or unknown CSV endpoints currently appear as blocked rows; validate IDs separately from service availability.

4. Matrix: travel times between sets of points

Save matrix.json. Add origins for N × 1, destinations for 1 × N, or both for N × M. Keep IDs useful to your application.

{
  "origins": [{"id":"home","point":{"coordinate":[-71.11902,42.37334]}}],
  "destinations": [{"id":"work","point":{"coordinate":[-71.08337,42.32978]}}],
  "mode": "transit"
}
node public/vigo.mjs matrix --city=./city --request=./matrix.json --service-date=YYYY-MM-DD --time=08:00 --output=./matrix-result.json

Transit supports depart-at and arrive-by; for the latter use --time=09:00 --time-preference=arrive. Walk and Drive use the respective mode and coordinate endpoints, with a static street metric. An arrival flag does not introduce time-varying traffic into street Matrix.

Up to 100,000 pairs are accepted in one request. Rows remain in origin-major order. Inspect each row's status; top-level ready does not mean every pair is reachable. Matrix has no waypoints or departure windows.

Journeys, geometry, and limits

For transit, add "includeJourneys":true for timed legs, walking, waiting, and transfers. Add "includeGeometry":true for selected path geometry; it requires journeys. Scalar arrive-by rows use the requested deadline as arriveMinutes, so their duration includes waiting after early arrival. The nested journey reports actual arrival.

Transit supports maxTransfers, requireTransitRide, and horizonMinutes as in Route. Street Matrix accepts maxDistanceKm and walking walkSpeedKph (default 4.8). disableCache:true on transit Route/Matrix disables access/path caches, while retaining the prepared network.

5. Reach, Scenario, and Compare

Reach computes scheduled transit plus walking from one origin, departing at a fixed time. Save reach.json:

{
  "origin": {"coordinate": [-71.11902,42.37334]},
  "cutoffsMinutes": [15,30,45],
  "extentRadiusKm": 6,
  "rasterSize": 48
}
node public/vigo.mjs reach --city=./city --request=./reach.json --service-date=YYYY-MM-DD --time=08:00 --output=./reach-result.json

Cutoffs range from 5 to 240 minutes, extent from 1 to 40 km, and walking speed from 1 to 8 kph. Supported grid sizes are 48, 64, 96, 128, 192, 256, 384, 512, and 1024. Extent limits computation, not just display. Reach has no Walk-only, Drive, arrive-by, or realtime mode. It does not count jobs, people, or other opportunities.

Planned transit service and comparison

A Reach request can add a scenario with a name and a service change, for example:

"scenario": {
  "id": "direct-bus", "name": "Direct bus",
  "services": [{
    "operation": "add", "name": "Direct bus",
    "stops": [
      {"coordinate":[-71.11902,42.37334]},
      {"coordinate":[-71.08337,42.32978]}
    ],
    "headwayMinutes": 10, "startMinutes": 420,
    "endMinutes": 1200, "averageSpeedKph": 22
  }]
}

This is a member to insert into the Reach object, not a complete standalone JSON document. Planned service applies to Reach only. See the Scenario reference for augment, replace, branch selection, route removal, and travel-time assumptions.

Save baseline and alternative Results, then compare them without rerunning either query:

node public/vigo.mjs compare --before=./reach-result.json --after=./reach-alternative.json --output=./comparison.json

Compare accepts compatible Route, Matrix, or Reach Results of the same family. Match endpoints/rows and, for Reach, grid bounds and resolution. Keep date/time and walking assumptions aligned when attributing a difference to the Scenario.

Traffic and live transit: actual support

Drive Route/Matrix accepts a top-level traffic snapshot. VIGO does not fetch a traffic provider. Use source, a current ISO observedAt, positive ttlSeconds up to 1800, and directed observations:

{
  "fromCoordinate": [-71.11902,42.37334],
  "toCoordinate": [-71.118,42.374],
  "delayFactor": 2
}

Each observation chooses exactly one of delayFactor (1–100), speedKph (1–200), positive travelTimeSeconds (at most 86400), or closed:true. Coordinates must match the intended directed edge. Supplied times cannot beat base free flow. Check matching counts and diagnostics.traffic.status; expired data falls back to free flow. Freshness uses the current clock, not the service date.

Realtime Route processes supported Trip Updates in the desktop and CLI. CLI callers supply realtimeSnapshot and select --data-mode realtime. Unreported trips retain scheduled times. Vehicle Positions and Alerts are display data; Matrix and Reach remain scheduled. See realtime modes and limits.

6. Build Studio or your own application

After the source build, npm run studio launches the desktop preview. npm run dev starts browser development; open its printed local URL. To create a standalone Studio package on the current target machine:

npm run build:studio
npm run check:packaged
npm run archive:studio
PlatformOpen this packaged application
macOSrelease/VIGO Studio-darwin-arm64/VIGO Studio.app or the darwin-x64 directory.
Linuxrelease/VIGO Studio-linux-x64/VIGO Studio or the linux-arm64 directory.
Windowsrelease/VIGO Studio-win32-x64/VIGO Studio.exe.

npm run release:studio combines icon checks, build, packaging, packaged checks, and archiving. Run npm run check:release for the full source/native suite. These commands produce local files; they do not publish Git tags or releases. macOS receives an ad-hoc signature, not Developer ID notarization. Build separately for each OS/CPU and retain the whole distribution, including resources.

Studio imports GTFS and OSM into its own project library. It does not open CLI City directories and has no Matrix screen. Its packaged interface communicates with Engine internally and opens no local server port.

For your own app: use the public CLI's JSON contract or the Python API. Studio's internal HTTP endpoints are not a supported external API. An HTML page can display an exported Result, as below; a static page cannot execute the native routing engine by itself. Live queries need a local native host or your application's backend.

Build the City before accepting queries, reuse it, and select the matching runtime explicitly in deployment. Starting a CLI process for each query includes reopening costs. Python provides resident execution for supported query types; its lifecycle and API details remain in the Python repository.

7. Read the answer first

The exported JSON preserves both the answer and substantial engine diagnostics. Most application code only needs the fields below. This is a reading guide to the existing schema, not a new response format.

QuestionExisting fields
Did it work?kind, status. A blocked Result is valid; CLI errors exit nonzero with stderr.
What is the journey?result.durationMinutes, departMinutes, arriveMinutes, transfers, legs.
What are the pairwise times?rows: IDs, per-pair status, duration, and optional journey.
What goes on the map?Route leg coordinates; Reach contours (GeoJSON). Reach surface is the raster for numerical analysis.
How should I interpret it?warnings, query/date, City identity, schedule mode, and station/street-access verification fields.
How did the engine execute it?diagnostics, searchStats, cache counters, candidate lists, and detailed timing. These usually belong in an expanded technical view.

Keep meaningful uncertainty visible. Station-access status and schedule fallback can currently live inside diagnostics; do not discard that entire object blindly. A path to a platform coordinate does not establish an entrance connection. Read the routing limits for unsupported GTFS features, station assumptions, street coverage, driving turns, and realtime boundaries.

Smaller JSON and simpler JSON are different. Removing indentation reduces bytes; separating the user answer from search and cache internals reduces the application's burden. The current API is unchanged.
