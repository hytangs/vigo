# VIGO 1.0.0-rc.3

This is the third VIGO 1.0 release candidate. Journey windows, Reach and Studio's wheelchair routing do less repeated work, and idle processes hold less memory. Every Route, Matrix and Reach answer is the same as in 1.0.0-rc.2; only timing fields differ.

## Journey windows do less repeated work

A departure window ranks many candidate journeys and returns a few. Candidates are now ranked without copying their lines, intermediate stops, endpoint details and descriptive trip fields; only the returned choices carry them. With a wider walking limit, the wider search's shared services are searched only for the choices that survive merging with the preferred walking limit.

Arrive-by windows reuse a recent identical walking path instead of searching it again at every sampled deadline. A scheduled window whose samples all use one timetable, which includes every scheduled arrive-by window, searches shared services only for the choices it finally returns. Other windows search them for the choices each sample keeps. `disableCache` still searches every path.

Reach rasterizes large street surfaces on up to four threads. Each cell keeps the minimum duration over all street segments, so the surface is the same as a single-threaded one.

One-shot command-line queries exit after writing their answer, without first freeing the City's memory piece by piece.

## Studio

Studio opens the wheelchair City only once wheelchair routing is selected, then keeps it ready while Route stays open, so toggling back and forth does not reopen it. An unselected wheelchair profile no longer repeats every date's preparation or holds a second City in memory. Studio leases the wheelchair City that answers wheelchair routes, and releasing it no longer fails when that profile was rebuilt or removed.

Depart now and the warmed realtime view use GTFS service time on daylight-saving days, including the repeated fall-back hour.

## Memory

A single-City `vigo stream`, which Studio and VIGO Python use, frees its street search scratch after 30 seconds without a request. On Linux with glibc those pages return to the system; other allocators may keep them for reuse. The next query allocates the scratch again; caches and prepared timetables stay. Set `VIGO_IDLE_RELEASE_MS` to change the delay, or `0` to keep the scratch.

The inactive-timetable budget starts at 128 MiB, or 1/32 of a smaller memory limit. Unless `VIGO_TIMETABLE_CACHE_BYTES` sets it, a standalone City's budget now grows to twice the size of a prepared view it retires, up to 1/16 of detected memory. A large City such as New York, whose prepared view exceeds half the default, previously prepared its other service day again on each switch; arrive-by windows near the start of the day switch on almost every query. Collections keep their fixed budget.

## Compatibility and packages

API 1.0, City format 1 and Result schema 1 remain unchanged. Compatible prepared Cities remain readable without rebuilding, and the frozen reference compatibility fixture remains part of release validation.

The corresponding Python version is `1.0.0rc3`. Engine tags use `v1.0.0-rc.3`; Python tags use `python-v1.0.0rc3`. Bundled Python runtimes come from the same repository commit.
