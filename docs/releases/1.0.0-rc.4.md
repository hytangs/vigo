# VIGO 1.0.0-rc.4

RC.4 adds bicycle Route, Matrix and Reach to the shared Rust engine, command line,
HTTP API, Python and Studio. Choose Bike in Studio, or use `"mode": "bike"` in a request.

Studio's route line view now fits beside the floating sidebar. The header
stays above the diagram when its controls wrap, and crowded vehicle labels
wrap within their direction instead of being clipped.

CLI builds opt in with `--street-modes=walk,bike` or `walk,drive,bike`.
Studio OSM imports prepare bicycle streets. Existing Cities retain their
walking, transit and driving behavior; add bike streets from the original OSM
source to enable the new mode.

Balanced, quiet and fast preferences share one optional graph, loaded only
on a bike request. Bicycle permissions, contraflow, barriers, surfaces,
mapped incline, dismount sections and turn restrictions influence the path.
Preference penalties do not inflate the travel-time estimate. Endpoint
connectors remain unverified walks; dismount sections are shown as walking
the bike. Journeys expose bike legs and separate cycling seconds.

This release does not establish parity with leading bicycle engines.
Terrain elevation, regional legal defaults, bike sharing and
bikes aboard transit remain outside the implemented scope. Dated depart-at
requests can evaluate supported weekly road access, directions, dismount periods
and node-turn or via-way restrictions, including waits or detours. Dated point
arrive-by requests evaluate those permissions too. Ordered arrive-by, unknown
conditions and requests without a usable clock remain conservative;
unsupported relation shapes are counted in diagnostics.

No routing dependency was added. API 1.0, City format 1 and Result schema 1
retain their existing field meanings. The optional bicycle tables are
ignored by historical readers; the frozen historical City remains unchanged.

See [bicycle requests](../guides/rust-standalone.md#bicycle-route-and-matrix)
and the [prepared-data contract](../reference/city-format.md).

RC.4 also adds opt-in native Monte Carlo Route, Matrix and Reach distributions,
with coherent frequency phases, seeded repeatability, end-exclusive departure
windows, fixed exact schedules and unreachable-inclusive percentiles. Planned
services support exact schedules and validated stop-to-stop phasing. Optional
opportunity indicators include five decay functions and dual accessibility.
Studio exposes simulation controls and retains settings in exports. See the
[method, examples and boundaries](../guides/monte-carlo.md).

Python `1.0.0rc4` exposes bicycle preferences and `monte_carlo` on Route,
Matrix and Reach. The Node CLI forwards simulations to the same resident Rust
sampler. Python retains distribution provenance, supports row-wise CSV export
and compares matching marginal percentiles without inventing journeys.
Existing query and build defaults remain unchanged, and older runtimes reject
unsupported opt-in features before a query starts. See the
[Python reference](../../python/docs/reference.md#bike-and-monte-carlo-options).

Ordinary transit timetables do not allocate simulation or phasing state.
Fixed-grid bounds are allocated on demand. Sampling code stays outside the
ordinary stateful transit scan. Prepared transit files remain unchanged.

New City builds now treat exact GTFS frequency end times as exclusive, avoiding
an extra departure where service ends or its headway changes. Existing City
files keep their stored trips; rebuild from source to apply that correction.
Scenario timetable rows support independent windows, ISO weekdays, copying and
exact or sampled departures without changing the City format.
Preserved-trip scenarios can independently scale moving time and scale or set
dwell, including selected segments and stops in the native API. Studio exposes
whole-pattern controls. The original first departures remain fixed.

Monte Carlo Matrix reuses endpoint preparation and direct walks across draws,
stores duplicate pairs once, and checks output limits before routing. Reach
skips street propagation that cannot enter the requested grid without changing
its cells. Bicycle searches use smaller temporary labels and index arrays;
the optional retained graph is still shared by all preferences.
Failed bicycle searches can retry endpoint candidates within the requested
walking limit, including alternatives to a directed dead end. Temporary
candidate storage is bounded, and all direction and turn constraints remain
in force. Successful nearby matches retain their existing route.

New bike imports preserve compact weekly turn windows without changing base
table meanings. A bicycle-specific conditional exception now retains the general
restriction outside its window. Older readers can ignore the optional windows
and keep conservative turn enforcement. Dated searches first check whether the
best static candidate is legal at its actual entry times. If it fails but no
schedule changes within the duration bound of any improving route, fixed
permissions still avoid arrival-clock labels. No new routing dependency was added.
Dated searches bound their remaining travel cost and waiting cost with temporary
indexes, and try permitted endpoint alternatives before accepting a long wait.
Excessive temporal search work returns an explicit error.
Supplemental timed road edges leave the conservative legacy graph readable by
earlier bicycle engines. They share compact schedules and one resident graph
across profiles. Direction-specific bicycle permissions now apply only in their
stated direction and no longer hide an unrelated generic conditional restriction.
Graph loading reserves coordinate and edge arrays from actual table counts to
avoid geometric over-allocation.
Incoming edges mark applicable turn rules in spare in-memory attribute bits.
Ordinary edges skip restriction-map lookups, and movement checks reuse one
lookup without adding resident arrays or changing City tables.
Compiled via-way windows now use the same schedule pool and movement clock as
node turns and road access. No-turn completion and only-turn continuations can
wait for a legal movement. Distinct continuation states after waiting remain
separate in the search, including overlapping only-turn alternatives.

Ordered bicycle routes retain turn history across waypoint boundaries, including
points inside a directed road and repeated points. This fixes a restriction
bypass caused by restarting each segment without its incoming road. A road
entered while open remains traversable past an interior waypoint after its
entry window closes. Segments use sequential route selection; they do not
promise a globally optimal path through all waypoints.

Bike Route and Matrix accept an optional `bike.maxLts` ceiling (1–4) on newly
prepared Cities. Higher-stress links require permitted bicycle pushing or are
excluded. OSM estimates account for direction, explicit LTS overrides and
unsignalized intersections; they are not measured safety. Stress data occupies
spare bits in the existing resident edge word. Studio adds compact bike profile,
speed and stress controls, and labels these dismount sections “Walk bike.”
Existing Cities and requests without the ceiling preserve their prior behavior.

Bicycle Reach now samples routes to or from grid points, preserving bike preferences, stress limits and physical travel times. Depart-at grids share a checked lower-bound tree with exact fallback. Dated point arrive-by queries can certify timed paths by replaying full turn history from the departure implied by the deadline, including backward-window bounds. When certificates fail, a bounded departure-profile search handles changing permissions and waiting while preserving the forward turn history. Route reports actual early arrival, while arrive-by Matrix and Reach include slack before the deadline. Search-limit failures are explicit errors. Arrive-by grids share a bounded destination-side tree with full forward verification and exact fallback. Ordered dated arrival routing remains open. Studio reuses Bike controls in Analyze and preserves them in point inspection and saved results.

Dated bicycle Reach now includes departures before midnight when its arrival
deadline requires them, keeping Route, Matrix and Reach on the same absolute
clock across daylight-saving changes. Weekly permission searches revisit an
opening skipped by a clock jump, including non-hour changes and skipped civil
dates, while retaining the event limit and the existing resident graph.
Its default arrival clock lookback now matches point Route/Matrix, independently
of the displayed cutoff. A shorter cutoff can exclude a preferred detour; it
cannot silently substitute a faster, higher-stress route.

New imports retain valid walking, driving and bicycle segments longer than
10 km, preserving original nodes, directions and supported bicycle windows.
The road attachment grid bounds duplicate edge references by coarsening its
cells; exact projection and permission checks still determine candidates.
Invalid geographic coordinates fail import explicitly. Existing fixed-point
distance limits still apply during street preparation; this does not add
unlimited-length edges or terrain geometry. Rebuild from OSM to recover
segments omitted by an earlier importer.
Node selection also retains cycleways with supported weekly bicycle access
when walking is prohibited and no other imported layer needs their geometry.

Departure grids can reuse a shared path through wider endpoint matches after
the primary search proves that its original matches have no path. Each reused
path still verifies destination access, turn history, distance and timed entry.
A route beyond the display cutoff does not itself authorize wider matching.
The primary tree keeps its existing label budget; incomplete searches and
unverified alternatives retain exact point routing.

New OSM imports share one facility-direction rule for bicycle access, comfort
and estimated traffic stress. Explicit side lanes and tracks can provide
contraflow in their mapped direction; opposite tracks no longer improve the
forward direction's comfort score. Road one-way direction takes precedence
over driving-side defaults, and directional facility exclusions are respected.
Supported weekly road reversals retain the matching facility, stress and
pushing permission for each interval. Junction stress comes from other ways
meeting the road, without copying its own opposite-direction stress across
every geometry vertex. These changes use the existing optional bicycle edge
fields and require rebuilding from OSM to update an existing City.

Newly prepared Cities connect bicycle endpoints through the existing public
walking network. Access and egress follow mapped directions, count their actual
distance, and expose verified pedestrian geometry. A footpath at the same
coordinates as a bridge or separate road does not connect without a shared OSM
node. The join is optional and shares the pedestrian snapshot; no second walking
graph or per-profile copy is created. Older Cities retain their previous
coordinate-attachment behavior until rebuilt. Short off-network coordinate snaps
remain explicitly unverified.

Bicycle Matrix now deduplicates coordinates and shares bounded search fields for
larger departure rows and arrival columns. It verifies both travel time and
physical distance, using point routing for ambiguous ties and uncertified paths.
The additional distance output and tie tracking are query-local; Reach does not
allocate them. No additional graph or persistent endpoint cache is retained.
Node Matrix requests with ordered bicycle waypoints now retain the sum of the
segment distances instead of returning a non-finite distance.

Shared bicycle searches now use smaller temporary records and release forward
trees before full point fallbacks. Route choices, physical time/distance and
search limits are preserved; the change applies to both Matrix and Reach.

Departure Reach also shares a restricted search among destinations
with identical road-access permissions when verified pedestrian attachments are
available. Restricted shortcuts remain forbidden, and timed waits and distance
limits retain point-router verification. Group keys
are bounded to 512 KiB per request, with one additional field active at a time;
no prepared-data format, dependency or transit-search change is required.

Bicycle pedestrian access now uses a 16-byte queue record instead of 24 bytes,
removing a duplicate distance while preserving distance/node tie ordering. Its
compact-node labels use the existing integer hash and one lookup per improving
label. Queue capacity and search limits are unchanged, and no persistent
workspace or endpoint cache is added.

Monte Carlo responses move their completed percentile arrays into public and
detailed output, avoiding a second full result copy. Saved Reach comparisons
require matching simulation windows, percentiles, draw counts and seeds, and
do not compare a simulation against a single-departure result.
Opportunity summaries also avoid copying completed layers and skip destination
sorting when no dual accessibility thresholds are requested. Opportunity
options deserialize directly from the request, avoiding intermediate copies
of the count arrays.

Studio waits for a stopped runtime's error stream to close before classifying
a City startup failure. This preserves missing/stale preparation diagnostics
so the existing repair path can prepare the selected network and retry.

Unused bicycle bookkeeping occupies one optional pointer in a transit-only
City. Frequency-phasing tables allocate only when explicit dependency rules
are installed; ordinary and independently sampled service retain no such table.
The bicycle memory ledger includes its separately allocated bookkeeping.
