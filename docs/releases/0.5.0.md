# VIGO 0.5.0

Studio makes journey comparisons easier to scan and uses less memory when driving is not needed. Routing objectives, station access rules, transfer minima, and timetable precision are unchanged.

## Studio

Journey cards show total time from the requested departure, transfers, walking, and the tradeoff against the earliest arrival. Sort the returned choices by earliest arrival, fewer transfers, or less walking. Arrive-by choices rank by latest departure. Sorting does not rerun the search. Arrow keys, Home, and End move between choices, with one keyboard tab stop for the list. Closing the itinerary preserves the selected journey on the map. The itinerary header uses the same total-time basis as its card.

Obsolete light-mode style overrides are replaced by shared theme rules. Old alert-scope reconstruction and saved-answer rewriting are removed; current notices use their original selectors and saved answers display their stored text.

Shared surfaces use a quieter palette, consistent control corners, readable journey metrics, and fewer repeated badges. Light and dark themes retain visible focus and reduced-motion support.

Opening a City prepares walking. Driving opens when Drive is selected or a driving operation requires it. A driving request received during walking preparation upgrades the shared job. This avoids retaining a second street network for transit-only work. The replaceable browser cache has a 64 MiB budget; City sources and retained runs are separate.

## Data and responses

Prepared snapshot headers use lossless gzip compression for large metadata blocks. Numeric arrays retain their aligned layout for native reading. Access snapshots store repeated transfer evidence and stop records once; Node restores shared records when loading. The source transfer costs, evidence, and directed station paths are preserved.

VIGO 0.5.0 uses one snapshot format: compressed metadata and aligned numeric arrays. The old uncompressed header and access-context readers are removed. Rebuild prepared Cities with 0.5.0 before using the standalone runtime. Studio regenerates rejected derived caches from the imported source stores.

Street hierarchy files use a compact v2 layout: seven aligned query columns, with no stored inverse rank or redundant arc tails. Walking files omit input-arc mappings after customization. Driving keeps those mappings in a losslessly compressed section, read only for traffic updates. Writing uses a 16 KiB scratch buffer instead of copying a full graph column. The v1 hierarchy reader and local-ID serialization layer are removed. Build new standalone Cities from source. Studio prepares a missing current hierarchy from its admitted street snapshot, with progress in the existing preparation job; driving remains on demand.

Transit shapes stay in one native cache. Rust clips each selected leg into a reusable 8 KiB buffer; JavaScript receives only its displayed points. Source-order alignment, endpoint selection, and sampling are preserved. Node and standalone default to a 64 MiB shape cache with at most 1,024 shapes.

Studio returns one response shape that sends each journey once and excludes internal cache inventories. It retains full leg geometry, route times, data warnings, realtime status, and request timing. The internal Studio channel remains separate from the supported [Engine API](../guide.md#command-line). The hidden `_route-stream` command and its separate result envelope are removed. Use `stream` with an explicit `kind` on every query. VIGO Python 0.5 uses this same protocol and requires Engine 0.5; older-runtime fallbacks are removed. Public Result schemas remain version 1; alternatives exclude duplicate copies of the primary journey. Use `includeGeometry: false` for smaller point-routing responses and `diagnostics: "trace"` when the full internal evidence is needed.

## Deployment and packaging

HTTP deployments use the native `vigo serve` runtime and one [Docker/Compose configuration](../guide.md#deploy-the-routing-engine). The separate Node HTTP service and its Engine ZIP are removed; the Node CLI remains the preparation tool. Compose defaults to 2 CPUs and 2 GiB, read-only City data, bounded queues and caches, and limited logs. `vigo health` checks readiness without loading a City.

Packaging replaces completed artifacts without accumulating a backup for every build. Failed replacements restore the previous package. The standalone archive verifies that its documentation matches the bytes embedded in the executable. CLI builds publish their output only after bundling succeeds.

Arrive-by reserves now adjust the service-day clock before applying the margin, allowing a buffer to cross midnight consistently in Route and Matrix.

Departure queries retain the cold-store direct-walk proof without opening the full transit store. Public service benchmarks validate the required Route, Matrix, and Reach outputs, distinguish malformed responses from HTTP failures, and apply deadlines through response-body reads. Unrelated aborts and connection resets remain transport errors.

Realtime reconstruction that exceeds the configured memory budget preserves its capacity error and 503 status through the routing worker. The resident scheduled timetable remains usable after the rejected request.

Reach rasterization records every grid cell crossed by a reachable street segment, including brief corner crossings. Studio derives detailed boundaries from the sampled surface and keeps display estimates separate from raw routing evidence. Direct-walking comparisons use the full query time allowance, and completed blocked results no longer appear to be loading.

## Reproduce the checks

- `cargo test --locked --manifest-path native/vigo-routing-kernel/Cargo.toml --no-default-features --features standalone --lib` checks compact hierarchy reloads, traffic customization, directed shortest paths against independent enumeration, and corrupt-file rejection.
- `node test/check-native-materialization.mjs` checks shape alignment and clipping against exhaustive reference implementations, including scratch-buffer ownership.
- `node test/check-routing-snapshot.mjs` checks exact compressed snapshot round trips, obsolete-format rejection, array preservation, and damaged-input rejection.
- `node test/check-prepared-access-compaction.mjs` checks fractional costs, transfer evidence, obsolete-format rejection, shared stop records, and size reduction on a synthetic public fixture.
- `node test/check-studio-route-response.mjs` checks retained journey evidence and failure status in compact responses.
- `node test/check-street-preparation-order.mjs` checks walking-only loading, on-demand driving, and concurrent requests.
- `node test/check-journey-options-runtime.mjs` exercises sorting and keyboard selection and renders both themes at desktop and phone widths.
- `npm run check:deployment -- --image IMAGE` exercises the actual service container, read-only City and scenario collection, authentication, queries, and restart.
- `npm run check:package-publication` verifies successful replacement and recovery from interrupted package publication.
- `npm run check:standalone` checks the prepared City format and public results across Node and Rust.
- `node test/check-service-benchmark.mjs` checks endpoint validation, unexpected statuses, non-JSON HTTP failures, connection resets, and header/body deadlines.
- `node test/check-national-routing-store.mjs` checks the cold-store walking proof and walking comparisons alongside transit routing.
- `node test/check-reach-geometry.mjs` checks boundary topology and conservative display estimates without changing raw samples.

Storage and memory reductions depend on the City and requested output. Hierarchy compression does not change street weights, transit objectives, or station-access rules.

## Retired compatibility paths

Cities must use exact-date GTFS service calendars. The former JSON timetable compiler and weekday-template store mode have been removed; rebuild those stores from source GTFS. Current GTFS Cities keep the same format.

Live-feed requests use `sources`, with explicit endpoint URLs and roles. Top-level `url` and `urls` aliases, viewer-URL extraction, and implicit expansion of one MBTA URL into three feeds have been removed. Reconnect old saved live-feed configurations through the feed editor. The explicit MBTA preset remains available.

The release checks now include grouped-feed routing and City data interactions. CLI and Studio share the same routing-result status classifier; unused status badges, status normalization aliases, and styles have been removed.

GTFS import rejects blank stop IDs before publishing a store, including scoped multi-feed builds. Tests no longer preserve that invalid-input behavior. Retired geometry and URL-validation wrappers have been removed; boundary, route geometry, and URL safety checks exercise the current production functions.

Public-source checks scan tracked files for private data, credentials, and machine paths. Dependency checks require public npm and crates.io sources, with local Rust paths confined to tracked source inside this repository. Replay fixtures reference the public VIGO repository.

On macOS, startup and background status checks wait for the user to open the City library before accessing Documents. The default Documents location and existing City files are retained. Health and settings status checks are read-only after opening as well. Invalid folder selections and malformed JSON return 400 without opening the library. macOS builds and release checks now target Apple Silicon only; Intel macOS is no longer a supported target.
