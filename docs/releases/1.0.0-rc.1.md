# VIGO 1.0.0-rc.1

This is the first VIGO 1.0 release candidate. Route, Matrix and Reach execute in Rust. Studio and Python use the public engine interfaces.

## Routing and integration

The `alternatives-v1` journey policy lets an API client request useful transit and walking alternatives in one call. Explicit walking limits remain binding; a wider limit requires explicit permission. The engine reports policy support through capabilities.

GTFS transfer rules, headway service, station access, shared-service information and all-day accessibility are handled by the native engine. Feed limitations remain explicit; this release does not claim support for every GTFS service model or untested deployment.

## Performance and Studio fixes

Ordinary timetable queries use fast CSA when conservative transfer certificates establish that it preserves the required semantics; exceptional cases retain the complete search. Street-transfer and wheelchair constraints remain binding. Reach avoids repeated label scans, street propagation skips empty radix buckets, and date changes reuse calendar-independent linked-trip preparation.

Studio starts rendering City data without waiting for basemap loading and defers detailed route inspection work. Journey choices collapse redundant alternatives, scheduled departure information remains visible, and new Studio builds prepare wheelchair networks. Scenario edits retain reusable definitions and safe save/reload behavior.

These changes address identified regressions, not universal latency guarantees. Opening several Cities for the first time and preparing new timetables still incur work; constrained-memory deployments should measure those separately from warm routing.

## Analytical output and workers

The Node CLI supports `stream --workers 1..4`, capped by CPU and memory capacity, with input-order responses. Non-geometric detailed Matrix journeys retain every timed leg without expanding per-cell Studio presentation records. Request `journeyFormat: "full"` or geometry for the additional display metadata. Native Matrix transport shares repeated journeys internally; public results retain their original cell order.

## Compatibility and packages

API 1.0, City format 1 and Result schema 1 remain unchanged. Compatible prepared Cities remain readable without rebuilding. The frozen reference compatibility fixture remains part of release validation.

The corresponding Python version is `1.0.0rc1`, the PEP 440 spelling of this release candidate. Engine tags use `v1.0.0-rc.1`; Python tags use `python-v1.0.0rc1`. Bundled Python runtimes come from the same repository commit.
