# VIGO 0.4.0

VIGO 0.4.0 brings live network inspection into Studio alongside journey planning and Reach analysis. It also adds individual City source deletion and fixes missing added-service trips.

## Network inspection

- **Network** shows reporting coverage, route comparisons, alerts, and service briefings.
- **Routes** provides trip times, station boards, and schematic line views. Route and station selections carry into **Ask**.
- **Ask** is an experimental model interface to transit tools, with sources and an inspectable activity trail. Model interpretations require review.
- Added realtime service appears in line views and the trip selector even without a static trip. Only reported stops and absolute predictions are shown; scheduled times and delays remain unavailable.
- Compressed spacing remains visible when predicted trip order reverses. Both matched vehicles receive the bunching marker, with the pair and reference stop shown in their details.

See the [Network guide](../network.md) and [vehicle timing](../network.md#vehicle-timing-and-line-view).

## Routing and City data

- Transit Route separates scheduled queries from immutable supplied realtime snapshots. Matrix and Reach remain scheduled. Added-service display does not extend the engine's [realtime routing support](../known-routing-limitations.md#realtime).
- Via-point routes disable unsupported transfer caps. Routing errors clear when a subsequent request succeeds.
- **City → Data sources** can delete an individual GTFS feed or OSM source. Remaining feeds, notebooks, and original input files are retained; dependent timetable bundles and OSM walking transfers are updated. See [source management](../studio.md#data-sources).
- Reach origins can be selected from imported stops or coordinates. Large reached-street displays reuse geometry and serialize source replacement when switching cutoffs.
- Map startup and Network keyboard focus are corrected. Browser checks now isolate fixture files and handle rendering consistently across supported targets.

## Compatibility

API 1.0, City format 1, and Result schema 1 remain unchanged. The Engine, Studio, and separate Python interface retain the City → Scenario → Query → Result model.

Studio uses the existing VIGO project library and storage defaults. CLI Cities remain portable directories; Studio does not open them directly. Build and install the native runtime for the target OS and CPU. See the [quickstart](../quickstart.md) and [known limits](../known-routing-limitations.md).
