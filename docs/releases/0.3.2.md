# VIGO 0.3.2

VIGO 0.3.2 improves Studio routing, GTFS inspection, and scenario editing. API 1.0, City format 1, and Result schema 1 are unchanged.

- Ordered waypoint routing preserves sub-minute arrival and departure times between legs.
- Studio Route uses coordinate map points with up to eight points total. Add, repick, reorder, reverse, remove, and rerun without resolving place names.
- Desktop and mobile share aligned navigation and contained playback controls. The GTFS inspector keeps service data visible and source details collapsed.
- Vehicles retain route-colored circles, with an inset arrow when a bearing is available. Feed trip totals are distinct from selected-date trip counts.
- Scheduled playback preserves shape variants, ordered loop visits, dwell, and overnight service times. Ambiguous live trip identities do not appear as a known isolated branch.
- Shared-edge scenario edits retain each branch's stop occurrences, geometry, and segment timing; inserted road paths remain continuous across successive segments.
- Local assets revalidate after updates. Build progress and documentation distinguish compiler-stage diagnostics from complete Build and first-answer timing.

Schedule playback is an estimate from the imported timetable. Scenario replacements use selected service windows and headways with modeled segment timings. See [known routing limits](https://github.com/hytangs/vigo/blob/v0.3.2/docs/known-routing-limitations.md) and the [Studio guide](https://github.com/hytangs/vigo/blob/v0.3.2/docs/studio.md).

The platform packages are built and verified by the release workflow for macOS Apple Silicon/Intel, Linux ARM64/x64, and Windows x64. Each package includes the native routing runtime. The developer guide is attached as a PDF.
