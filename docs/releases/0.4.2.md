# VIGO 0.4.2

VIGO 0.4.2 combines multiple timetables and live feeds, tightens realtime routing semantics, and improves memory admission and recovery. It also retains the native preparation and Matrix improvements from the initial freeze. API 1.0, City format 1, and Result schema 1 remain unchanged.

## Multiple timetables and live sources

Import multiple GTFS ZIPs into one City. Studio now accepts up to 16 GTFS-RT endpoints, including Trip Updates without Vehicle Positions. Match endpoints to static timetables; source identity survives decoding, operational inspection, routing and vehicle display. Duplicate IDs in different feeds remain separate. Individual feed failures and freshness are visible. See [setup and limits](../guides/multiple-feeds.md).

A stop-specific delay no longer becomes a trip-wide delay affecting earlier stops. Unknown relationships and unordered stop predictions are rejected. Unavailable endpoints prevent an all-complete coverage claim. FULL_DATASET snapshots remain the supported feed model; added/frequency/replacement routing and cross-timezone stores retain their documented limits. The [method audit](../development/realtime-audit-0.4.2.md) explains verification and exclusions.

Drive Route and Matrix support caller-supplied traffic costs and closures. No live traffic provider is bundled or configured. Results identify applied, expired, unmatched and baseline-equivalent traffic. See the [traffic contract](../reference/street-routing.md#supplied-traffic).

## Preparation, memory and recovery

- City builds retain Drive hierarchy structure and time/distance metrics. Reopening maps prepared files; missing required files produce a restore/rebuild error.
- Native Matrix execution shares endpoint work and timetable scans. Shape alignment and stable identifier arithmetic run in Rust; JavaScript still loads selected rows and assembles results.
- Timetable and cache budgets scale with host/container capacity. Requests, worker queues, operation duration and worker heaps have finite limits. Realtime download, decode and reconstruction work has additional admission limits.
- Studio retains its window through Engine crashes and attempts bounded automatic restart. Routing-thread failures release queued requests and allow subsequent preparation from authoritative City data.
- Packaged Engine excludes unrelated shell credentials and developer overrides. Recovery preserves the same application-data configuration.

These are bounded safeguards, not a guarantee against every native hang or operating-system memory failure. The [runtime guide](../development/runtime-recovery.md) lists exact limits and behavior.

## Cleanup and documentation

Remove simulated worker/provider infrastructure, global clock patches, browser spies and redundant canned-response suites. Keep generated input documents and actual routing, SQLite, browser, socket and process checks. The runtime guide records coverage lost when earlier fault simulations were removed.

Consolidate live-feed URL handling into one shared boundary and extract bounded inspection from the API coordinator. Retain old-City readers, saved-study access, replay inputs and notices with active consumers. Cleanup preserves those contracts rather than deleting files by age.

The README uses the existing VIGO GitHub social image. The [Studio tour](../guides/studio-tour.md) contains real application captures from fresh public MBTA/OpenStreetMap inputs, with provenance and reproduction steps.

## Final verification

The [architecture audit](../development/audit-0.4.2.md) records release checks, remaining cost centers and cleanup. Core checks include 1,536 realtime/literal-timetable comparisons, source-isolated multi-feed forward/reverse routing, traffic Route/Matrix parity, memory admission, actual worker/Engine recovery, City portability and package isolation.

Use `npm run check:release`, `npm run check:studio-runtime`, and `npm run release:studio` on the target platform. Local verification covers macOS ARM64; other-platform behavior and field ETA accuracy are not established by that run. No unmeasured speedup is claimed.
