# VIGO 0.4.2

VIGO 0.4.2 moves Drive hierarchy preparation into City builds, shares coordinate-access work inside native Matrix execution, and moves shape alignment and stable identifier arithmetic into Rust. API 1.0, City format 1, and Result schema 1 remain unchanged.

## Preparation and routing

- New Cities retain the Drive CCH structure and time/distance metrics. Fresh processes open those prepared files instead of rebuilding the hierarchy. Build time and City storage include this work. Older Cities marked ephemeral keep their existing behavior until rebuilt from source; missing required persisted files produce a restore/rebuild error.
- CLI startup prepares the requested routing mode. Matrix streams initialize each mode on first use and report that preparation on the initializing request.
- Coordinate transit Matrix keeps endpoint projection and optional direct walking in Rust. Public street attachments can be reused within the same request; private endpoint access is recomputed when its distance boundary differs. Cache-disabled requests still disable cross-request access/path reuse.
- Endpoint reduction avoids duplicate frontier vectors. One-to-many departure queries and many-to-one deadline queries retain shared native timetable scans and exact transfer-cap semantics.
- Native shape alignment retains monotone stop order and bounded candidate storage. Stable identifiers preserve Unicode and unpaired-surrogate behavior. **Materialization-critical computation has moved into the Rust kernel.** JavaScript still loads selected GTFS rows, assembles itinerary objects, and handles orchestration and interfaces.
- Realtime clock conversion reuses work within one snapshot, service date, and timezone, with DST and overnight regressions.

## Explanation and limits

Blocked access diagnostics distinguish straight-line proximity, verified path distance, and an unavailable diagnostic. The wider diagnostic search never enlarges the requested walking budget. Selected access legs expose street and declared station-pathway costs separately.

Long-edge pedestrian snapping remains limited by its vertex-based candidate search. Declared pathway time is source data, not independently verified walking speed. See [known limits](../reference/known-routing-limitations.md). These changes do not establish other-city performance or field accuracy, and no comparative speedup is claimed here.

## Distribution and documentation

Packaged Studio starts Engine with OS path/locale variables and its own runtime settings, excluding unrelated shell credentials and developer overrides. The unused environment-triggered screenshot hook is removed. Source and package checks share path/credential detection across file types, including Windows paths and UTF-16 strings. Version metadata and the printable-guide build derive from package metadata instead of separate version literals.

The stale README line-view screenshot is removed. Current guides describe the native ownership boundary, persisted Drive lifecycle, Matrix timing, and cache policy. Historical release notes remain unchanged.

## Verification

The repository supplies differential shape/identifier tests, directed Matrix and private-access parity, large shared forward/reverse queries, cache/lifecycle tests, CLI/City portability checks, environment-isolation fixtures, and packaged-runtime checks. Use `npm run check:release`, `npm run check:studio-runtime`, and `npm run release:studio` on the target platform. Passing a local build establishes that host's result; the CI matrix checks the other supported targets.
