# Ask audit — September 15, 2026

**Ask is not yet dependable for expert operational judgment.** The broader audit found useful timetable and vehicle answers, but also wrong route identities, unsupported causes and forecasts, and incomplete comparisons. Successful tool execution did not establish that the resulting answer was correct.

## What was tested

The audit covered **60 distinct questions and 173 actual model attempts**, including retests, through the real Ask loop and tool registry. Configured models were `qwen3.5-flash` and `qwen3-omni-flash`, using the user-authorized temporary OpenAI-compatible endpoint. These labels describe the requested models, not independently verified hosting. The credential was held in process memory and child-process environment, never written to source or evaluation records. The test runner has been stopped.

The corpus combines [32 operational questions](../test/fixtures/intelligence/questions.json) with [28 additional queries](../test/fixtures/intelligence/query-cases.json): GTFS SQL and calendar coverage; station boards; particular vehicles; occupancy; retained prediction history; cancellations, skipped stops and missing updates; stale feeds; multi-route comparisons; rider messages; follow-ups; clock and deployment questions. Expected answers are withheld from the model. Follow-ups receive prior conversation evidence; the stale-feed case changes feed timestamps before recomputing observations.

All model runs use the same [synthetic network](../test/fixtures/intelligence/scenario.mjs): seven routes, five stops and 84 trips, frozen at September 14, 08:00 EDT. Boston names are fixture labels, not Boston service observations. There is one Route 66 cancellation and a FULL occupancy report; construction applies to Route 39, not every delayed route. No APC counts, crew assignments, fleet readiness, maintenance records, actual passage history or validated recovery model are supplied. The live clock question uses server time. This fixture has no journey adapter; it does not replace the separate native routing tests or establish routing speed.

The [retained audit record](evidence/ask-broad-audit.json) includes run settings and timing, all 60 latest primary-model answers, requested tool arguments, expected outcomes, individual reviews, and 21 selected Omni comparisons. Explicitly labelled private drafts are omitted from published answers. Full technical traces remain in ignored local evaluation files. This is a coding-assistant review, not an independent operator study or a comparison against TransitGPT.

## Defects repaired

| Failure observed | Change and verification |
| --- | --- |
| Trip ranking answered five trips per route instead of twelve; stop counts omitted an endpoint. | Made read-only GTFS SQL available without a discovery round. Clarified counting grain and the union of connection endpoints. Retests returned twelve trips and five stops per route. |
| A cancelled trip assignment inflated Route 66's vehicle count to six. | Clarified use of the existing fresh-position roster. Retest correctly returned five. |
| Vehicle 1827's history disappeared because its next compared stop differed from the stop with retained forecasts. | Preserve separate, bounded histories by stop, with local clocks and computed changes. Retest recovered a ten-minute increase over eight minutes; these remain forecast changes, not actual movement or incident onset. |
| The vehicle evidence check omitted occupancy categories that the feed supplied. | Return scoped, fresh position reports and their occupancy categories. Regression checks distinguish unknown occupancy from a reported FULL category. The model still sometimes ignores the second requested entity. |
| An explicitly requested 90-minute window was calculated, then dropped from the model's compact evidence. | Preserve the requested horizon through compaction, including 77 scheduled trips, one reported cancellation and 36 without matched reports in this fixture. A later model replay still chose the wrong evidence check: the data fix does not solve that selection error. |
| A supporting station board prematurely finished an operational assessment. | Keep the assessment open after supporting board retrieval. A regression exercises inspection, board lookup and final composition together. |
| Explicitly labelled private drafts reached the answer instead of a finished response. | Accept a separate public final answer or use the existing bounded retry. Preserve that retry instruction during assessment composition. This handles the observed labelled format, not every possible unlabelled draft. |
| Notice epoch timestamps were misread as local operating hours. | Project notice periods into the agency timezone before composition. Tests verify 07:30–09:00 EDT and retain the distinction between notice display periods and incident onset/recovery. |

No routing kernel, Reach engine, UI layout or provider connection default was changed in this audit.

## Remaining answer failures

The latest retained primary-model answer for each question was manually reviewed: **23 acceptable, 15 partial, 22 failed**. “Acceptable” means the essential request was supported in that one replay. Partial answers contain a material omission or qualification; failed answers have a wrong decisive fact, scope or entity, unsupported operational claims, or no usable answer. Selected retests replaced their own earlier answers; most operational questions were not rerun after the final small projection changes. These counts are not a production accuracy estimate.

The most consequential failures remain:

- **Entity binding:** a Red Line question was answered as “Red Line (Route 39)” using Route 39's construction evidence.
- **Time and causal inference:** first retained forecasts became incident onset; scheduled exposure became a 90-minute persistence forecast. Absence of a notice became evidence of a different cause.
- **Dispatch and capacity:** the model claimed an optimal spare-bus placement without demand or feasibility data, treated reporting vehicles as an available fleet, and inferred excess demand from an occupancy category. Earlier attempts also invented hold durations.
- **Incomplete comparisons:** a question about vehicle 1827 and Route 66 checked only 1827, then incorrectly denied occupancy evidence for Route 66.
- **Coverage arithmetic:** a 90-minute question selected the position-report check and claimed zero unknown trips instead of 36. Omni retrieved the 36 but incorrectly subtracted the cancellation again.
- **Evidence-source confusion:** Omni denied retained vehicle history because no LAMP study existed. Current retained forecasts and historical LAMP studies are separate resources.

Prompt reminders reduced some mistakes but did not reliably prevent these errors. The next focused improvement should bind each requested output to its exact entity, time window and evidence result before composition, and keep proposed hypotheses and actions separate from computed facts. It should not add more dashboard panels or assume that another tool call guarantees a better answer.

These are single-run cloud diagnostics. Both reasoning settings and harness behavior changed, and provider load was uncontrolled; this is not a controlled speedup claim. The baseline operational run emitted five explicit private drafts; its first retest emitted none. The app's saved connection settings were not changed. Alibaba documents the compatible [chat API](https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions) and [thinking controls](https://www.alibabacloud.com/help/en/model-studio/deep-thinking).

Three of Omni's 21 selected attempts encountered HTTP 429. Those are availability failures, not evidence of poor reasoning. Further requests were stopped; the evaluator now stops automatically at the first recorded rate-limit response, preserving completed answers and recording that remaining questions were not attempted.

## Reproduce and inspect

The opt-in evaluator takes a configured endpoint through the existing `VIGO_AGENCY_LLM_*` environment variables. Set credentials privately in the process environment; do not put them in command history or a committed file. Normal regression checks make no paid model requests.

```sh
node scripts/evaluate-agency-intelligence.mjs --output temp/operations-new.jsonl
node scripts/evaluate-agency-intelligence.mjs \
  --corpus test/fixtures/intelligence/query-cases.json \
  --output temp/queries-new.jsonl
npm run check:agency
```

Output paths must be new. `--ids` selects cases; include the earlier prerequisite for a follow-up. Use the published [GTFS-RT reference](https://gtfs.org/documentation/realtime/reference/) when reviewing cancellation, skip, trip-instance and missing-update semantics. Neither missing reports nor prediction timestamps establish actual service passage.

Final validation passed the complete Agency regression suite, application/CLI build, and packaged macOS arm64 runtime check, including City preparation and Route parity. The packaged application also passed strict code-signature verification. These checks establish the tested software behavior and packaging, not the quality of arbitrary model answers.
